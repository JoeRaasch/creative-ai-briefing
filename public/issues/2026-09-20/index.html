01 · Unreal / ComfyUI

Two Unreal plug-ins turn ComfyUI into a live previz backend.

CG supervisor Kevin Bertelli built two Unreal Engine plug-ins that push generation out to ComfyUI without making artists leave the engine. One sends a prompt through Z-Image Turbo and Pixal3D to create a quick 3D prop that loads into the scene; the other captures the current Unreal camera, restyles it with Qwen Image Edit, then projects the result back onto the geometry so the look can be explored in real time.

His setup runs ComfyUI on a second computer so Unreal keeps its VRAM, and the projection tool adds masking, feathering, field-of-view controls and multiple captures to reduce projection artifacts.

Why it mattersThis is the kind of hybrid AI workflow worth teaching: the model accelerates asset and look exploration while camera, geometry, composition and revision stay inside a familiar real-time pipeline. It is aimed at previz rather than final asset quality—which is exactly what makes the architecture credible.

02 · ComfyUI production

Director’s Console is becoming an open-source production layer for ComfyUI.

Director’s Console combines cinematography-aware prompt rules, a storyboard canvas, media gallery and an orchestrator that can dispatch image and video generations across multiple local or remote ComfyUI nodes. Its current codebase supports imported ComfyUI workflow JSON, editable parameter extraction, per-panel workflow assignment and node monitoring for VRAM, RAM and queue depth.

The project is now MIT licensed and is being actively updated, but its own documentation warns that it is not security-audited and is intended for trusted, access-controlled networks rather than exposure as a public service.

Why it mattersFor a lab or small studio, this is a more interesting direction than another model demo: it turns several machines and arbitrary ComfyUI graphs into something closer to a production desk. The architecture is inspectable and adaptable, which makes it especially useful for experimenting with distributed creative-AI workflows.

03 · Tiny local agents

Needle 3 squeezes local tool-calling into an 8–29 MB model.

Cactus Compute released Needle 3, a tiny automation model built for tool selection, argument filling, structured extraction and embeddings rather than general chat. A single laddered weight set can be deployed at different depths, with footprints from roughly 8 MB to 29 MB, and prebuilt runtimes target devices ranging from desktops to phones, robots and microcontrollers.

Cactus reports that task-specific fine-tuning can push a 29M-parameter subnetwork past DeepSeek V4 Flash on its DroidCall tool-calling benchmark; that is a narrow vendor benchmark, not a claim of general model parity.

Why it mattersThis is a useful countertrend to giant local LLMs. Many creative-pipeline agents only need to route tasks reliably—launch a render, fill metadata, classify an asset or call a tool—and a specialized offline model this small could make those automations cheap, private and deployable on modest hardware.

04 · Coding agents

Claude Code adopts AGENTS.md and moves auto-mode classification server-side.

Two consecutive Claude Code releases changed the plumbing around coding agents: v2.1.277 falls back to AGENTS.md for project instructions when CLAUDE.md is absent, while v2.1.278 defaults supported API and enterprise environments to a server-side auto-mode classifier that avoids separate classifier-overhead charges. /status now shows where that classifier is running.

Why it mattersAGENTS.md matters more than the specific product: it pushes repository-level agent instructions toward a portable convention that can be shared across mixed coding-agent workflows instead of duplicated per vendor. For teaching agentic development, that is a good reason to treat instructions, tests and repo policy as versioned project assets.

05 · AI evaluation

Anthropic and Accenture are putting independent evaluators inside the frontier lab.

Anthropic announced an embedded-evaluation partnership with Accenture’s Faculty business: evaluators will work with access comparable to employees while red-teaming models, assessing alignment and testing safeguards. The two companies each expect to invest at least $1 billion over five years in building this evaluation capacity.

Anthropic says the operating details are still being worked out, so the significance today is the model of oversight rather than a finished standard.

Why it mattersFor studios and schools adopting increasingly capable agents, this is a signal that professional AI practice is shifting from “does it work?” toward “can we evaluate, document and constrain how it works?” That mindset belongs alongside model choice in production and curriculum.

Google Home now has an early-access MCP server

Google’s Home MCP can expose structures, device states, history and selected control actions to compatible AI agents. Sensitive actions such as unlocking doors are blocked, and Google explicitly warns developers to treat real-home access carefully.

Worktrunk makes Git worktrees friendlier for parallel coding agents

The open-source CLI wraps Git worktrees in a simpler workflow aimed at running several agents in isolated branches without having them overwrite one another. It is a useful pattern as coding work shifts from one assistant to several concurrent workers.

VibeTree turns parallel agent worktrees into a visual mission control

VibeTree gives each coding agent its own Git worktree and persistent terminal, then lets you inspect diffs and merge or discard each experiment independently. It supports Claude Code, Codex CLI, Gemini CLI, Aider and other terminal agents.
